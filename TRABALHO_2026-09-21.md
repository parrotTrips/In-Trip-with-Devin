## 1. Os dois problemas que iniciaram a sessão

### 1.1 "No data found for trip 'TEST-2026-FULL'"

**Não era bug de código.** Li a planilha pelo mesmo caminho que o backend usa e o erro
estava correto: o conteúdo da viagem existia, mas com a **coluna A (`trip_uuid`) em branco**.

| Aba | Linhas órfãs (sem `trip_uuid`) |
|---|---|
| Fases | L29–L31 |
| Checklist | L71–L82 |
| Roteiro | L6–L16 |

`filter_rows_by_trip` casa `row[0].strip() == trip_uuid`, então descartava tudo em silêncio.
Você preencheu a coluna e seguimos.

Ficaram duas observações que **não** foram tratadas: os links L2–L5 são órfãos de outra
viagem (fases `visa`, `vaccination`, `packing`, `documents` que não existem no TEST), e o
Roteiro usa `2026-08-24/25` enquanto a viagem vai de `2026-12-30` a `2027-01-10`.

### 1.2 Violação de chave estrangeira em `activity_checkin_scan_events`

Esse era bug de verdade. `write_to_db` apaga as atividades da viagem antes de recriá-las e
limpava as tabelas filhas — menos `activity_checkin_scan_events`, criada depois pela
migration `20260624_0011` e nunca incluída na limpeza. Com 473 scans de QR registrados no
`TEST-2026-FULL`, qualquer reimportação quebrava.

**Correção:** os scan events são log de auditoria append-only, então são **desvinculados**
(`SET NULL`), não apagados — a coluna já era nullable exatamente para isso. Decisão sua.

**Encontrei o mesmo bug, pior, em `admin_reset_content`** (menu "🗑️ Clear Trip Content"):
ele apagava atividades sem limpar **nenhuma** tabela filha. Corrigido junto.

Ficaram fora, com aviso: `scripts/reset_trip_content.py` e `scripts/seed_placeholder_trip.py`
têm o mesmo defeito, mas são CLIs locais. A lógica de limpeza está duplicada em quatro lugares
— extrair um helper resolveria os quatro.

**Arquivos:** `backend/scripts/import_trip_content.py`, `backend/app/services/admin_service.py`,
`backend/tests/scripts/test_import_trip_content_write_db.py` (novo, 2 testes).

## 2. A plataforma de conteúdo (console)

### Por quê

Os dois problemas acima não foram azar — são estruturais de planilha-como-entrada: sem campo
obrigatório, sem integridade referencial, com import destrutivo e sem rastro de quem mudou o quê.

### Decisões

| Tema | Decisão |
|---|---|
| Planilhas | **Intocadas.** Nada removido nem alterado; na prática viram leitura |
| Objetivo | **Paridade total** — a plataforma faz tudo o que as planilhas fazem |
| Onde vive | App novo e separado (`console/`), deploy próprio |
| Publicação | Rascunho + publicar, com a **fase** como unidade |
| Acesso | Papel `admin`, login por WhatsApp OTP |
| Criar viagens | Fora de escopo — continuam vindo do WeTravel |

### Mapa de paridade

Levantado lendo `Code.gs` e `CodeStaff.gs` inteiros.

| Fatia | Cobre | Status |
|---|---|---|
| **A** | Fases, Checklist, Links | **Concluída** |
| B | Roteiro (dias e atividades) | Não iniciada |
| C | Emergency Contacts, Recomendações, FAQ, Política de Cancelamento | Não iniciada |
| D | Staff, Contatos, Tarefas Staff, Participantes Atividades | Não iniciada |
| E | Start Trip, Reset Trip, Clear Content, ver Feedbacks | Não iniciada |

A fatia **E** foi uma correção de rumo: meu mapa inicial só tinha abas de conteúdo e esquecia
que o menu também dispara ações operacionais. Sem elas não há paridade.

**Não migram**, por existirem só para manter a planilha viva: `Setup Sheet Headers`,
`Import Trips from App`, `sync-to-sheet` e `write-staff-bios`. A aba **Viajantes Teste** foi
descartada por decisão sua.

### O que foi construído (fatia A)

**Backend — `/console`, 10 rotas**, todas exigindo JWT **e** `role=admin`:

```
GET    /console/trips                       lista viagens ativas
GET    /console/trips/{uuid}/phases         árvore: fases + checklist + links
POST   /console/trips/{uuid}/phases         cria fase (nasce em rascunho)
PATCH  /console/phases/{id}                 edita campos, incluindo datas
DELETE /console/phases/{id}                 recusa com 409 se houver atividades
POST   /console/phases/{id}/publish
POST   /console/phases/{id}/unpublish
PUT    /console/phases/{id}/checklist       substitui a lista, na ordem enviada
PUT    /console/phases/{id}/links           idem
PUT    /console/trips/{uuid}/phases/order   reordena
```

**Nenhuma migration.** O rascunho reusa `is_visible`, que já era filtrado pelo app do viajante
(`trip_service.py:142`) e pelo staff (`staff.py:264`) — uma fase em rascunho é invisível de graça.
E `users.role` é `Text` sem CHECK, então o valor `admin` é só dado.

**Frontend — app `console/`**, Vite + React + TypeScript + Tailwind, deploy independente.
Quatro telas: Login (OTP), Viagens, Fases e Editor de fase.

**Ganho central:** a edição é **incremental** (UPDATE por id), então os IDs sobrevivem. Editar
o horário de uma atividade deixa de destruir os check-ins dela — o oposto do import de hoje.

### Prefixo separado, e por quê

`app/middleware/auth.py:14` declara `_PUBLIC_PREFIXES = ("/auth", "/admin")`: **todo o `/admin`
pula o JWT**, porque o Apps Script chama sem token. Colocar o console ali exporia escrita de
conteúdo sem autenticação; movê-lo para dentro do JWT quebraria o Apps Script. O prefixo novo
`/console` resolve os dois.

## 3. Achados sobre o sistema

Coisas que encontrei investigando e que valem decisão sua.

### 3.1 Os endpoints `/admin` são públicos

`app/routers/admin.py:1` documenta: *"no JWT required, protected by network/sheet access only"*.
Qualquer um com a URL do Cloud Run pode apagar o conteúdo de uma viagem. Hoje se sustenta por
obscuridade. **Não alterei** — o Apps Script depende disso.

### 3.2 Respostas 401/403 saem sem CORS

`app/main.py:34-35` registra o `JWTAuthMiddleware` **depois** do `CORSMiddleware`, o que o torna
o mais externo. Quando ele corta a requisição, a resposta não passa pelo CORS e chega ao
navegador como erro de rede genérico, escondendo a mensagem real.

**Isso afeta o app do viajante:** qualquer sessão expirada aparece como falha de rede em vez de
"não autorizado". A correção é inverter duas linhas. **Não fiz** — é código em produção fora do
escopo pedido, e merece validação própria.

### 3.3 O link de pré-embarque já funcionava

```
https://parrot-trips.netlify.app/profile?section=pre-departure
```

Não precisou de nenhum desenvolvimento no app do viajante: `netlify.toml` já faz o fallback de
SPA, `ProfileScreen.tsx:290` já lê `?section=`, e nada navega após o login, então a URL sobrevive
ao OTP. O console apenas oferece o botão de copiar.

**Restrição:** só abre para telefone já cadastrado em `users` — `auth_service.py:109` responde
`403 "Phone number not authorized"`. O cadastro de viajantes segue pendente com os stakeholders.

### 3.4 Outros

- O domínio do frontend mudou: `parrot-trips-app-286` hoje redireciona para **`parrot-trips.netlify.app`**.
- Artefatos de `tsc -b` (`*.tsbuildinfo`, `vite.config.js`) tinham sido commitados por engano; removidos e adicionados ao `.gitignore`.

## 5. Erros que cometi

Registro porque afetam a confiança no que foi entregue.

**Três bugs seguidos no auto-login de desenvolvimento**, todos com a mesma raiz: eu testava se o
app *parecia* logado (`isLoggedIn`), não se a credencial *funcionava*.

1. O token só ia para o estado do React, não para o `localStorage` de onde o cliente HTTP lê.
2. Corrigi com `useEffect`, mas efeitos de filhos rodam antes dos do pai — a primeira requisição
   ainda saía sem token.
3. O `localStorage` tinha precedência sobre o `.env`, então trocar de banco deixava um token
   obsoleto sendo enviado.

Os testes agora disparam requisições reais e conferem o header `Authorization`.

**Outros dois:**

- Montei um banco Demo quando você queria ver os dados reais. Foi por segurança, para você não
  editar produção sem saber, mas eu deveria ter perguntado em vez de decidir sozinho.
- Afirmei que o redirect do Netlify descartava a query string. Estava errado; corrigi na hora.

Também descobri que o `.env` local contaminava a suíte de testes (o Vitest carrega `.env`, e
`VITE_DEV_AUTO_LOGIN=true` vazava). Os testes agora fixam a variável e não dependem da máquina.
